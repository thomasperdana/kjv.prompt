## 2. Definitions (lock these before writing)

- **Zero-to-Hero** — a single learning path with explicit levels: **L0 Novice → L1 First Study → L2 Repeatable Loop → L3 Verified & Guarded → L4 Stateful & Deep → L5 Hero (Automated)**. Each level adds exactly one capability and ends with a "you can now…" checkpoint.
- **Loop Engineering** — designing study as a *verifiable iterative loop*, not a one-shot question. A loop is "engineered" (not a hamster wheel) only when it has: (a) discrete named phases, (b) a **verification/feedback** mechanism, (c) **persistent state** that carries forward, and (d) an explicit **convergence / stop condition**. Repetition without these four is not engineering.
- **Hermes AI** — the open-weight LLM family from **Nous Research** (Hermes 3, Hermes 4, Hermes 4.3). Steerable via system prompt, supports tool calling and structured JSON, and runs **locally** — which is why it suits private, unrushed scripture study. (See §9 for verified specifics.)
- **KJV** — the **King James Version** (1611, Authorized Version), in the Textus Receptus / Masoretic tradition. The guide treats the KJV English as the authoritative study text, enriched by — never replaced by — the underlying Hebrew and Greek.
- **Ground truth** — the *verbatim KJV text*. Because the KJV is fixed, finite, and retrievable, it is the loop's anchor: every generated claim must be subordinate to a quotable, cited verse.

## 3. Non-Negotiables (bind every section of the guide)

1. **KJV-verbatim, always cited.** Scripture is quoted exactly from the KJV with book/chapter/verse. Never paraphrase scripture as if it were the text; never invent or misattribute a verse or cross-reference.
2. **Anti-hallucination by design.** Treat the model as wrong until checked against the text. Every theological claim names its supporting verse(s); every cross-reference is verified to exist and to actually say what is claimed.
3. **KJV-only for the base text.** Do not silently substitute or default to ESV/NIV/etc. Other versions or original languages may *illuminate*, but the study text stays KJV.
4. **Local-first.** Assume the reader runs Hermes on their own machine (`{{HARDWARE}}`). Cloud/API is an option, never an assumption.
5. **This file stays a prompt.** You are producing the *guide*; do not pre-write study devotionals here. The guide, in turn, produces *instructions and prompts* the reader runs — it does not pre-can someone's personal study.
6. **Doctrinal humility.** Where godly interpreters differ, present the major faithful readings and the texts behind them rather than flattening to one.

## 6. The Study-Loop Spec (canonical — the loop the guide teaches)

Teach this loop. Keep phase names stable so the reader can script them later.

```
        ┌───────────────────────────────────────────────┐
        │                                               │
        ▼                                               │
 [1 SELECT] → [2 GROUND] → [3 OBSERVE] → [4 INTERPRET] →│
 [5 CORRELATE] → [6 ILLUMINE] → [7 CHALLENGE] →         │
 [8 APPLY] → [9 RECORD] → [10 EVALUATE] ─────────────────┘
                                   │
                          score ≥ {{DEPTH_THRESHOLD}}?
                            ├─ no  → loop with the gaps as the next focus
                            └─ yes → CONVERGE (close the passage)
```

- **1 SELECT** — choose the loop unit (`{{TARGET_PASSAGE}}` or next unit).
- **2 GROUND** — paste the **verbatim KJV** text + references into context. *(Anchor against hallucination.)*
- **3 OBSERVE** — what does the text actually say? (terms, structure, repetition, who/what/when).
- **4 INTERPRET** — what did it mean to the original readers? (grammatical-historical).
- **5 CORRELATE** — cross-reference: let scripture interpret scripture; verify each reference exists.
- **6 ILLUMINE** — original-language word studies (Hebrew/Greek) and theological synthesis.
- **7 CHALLENGE** *(verification/feedback)* — red-team for eisegesis, hallucinated verses, KJV drift; **verify every citation verbatim**.
- **8 APPLY** — implications for belief and life; small-group/personal application.
- **9 RECORD** *(state)* — append findings, open questions, and applications to the **study journal**; this feeds the next iteration.
- **10 EVALUATE** *(stop condition)* — score the iteration on the depth rubric. If `≥ {{DEPTH_THRESHOLD}}` → **CONVERGE**; else loop, targeting the lowest-scoring dimensions.

Mapping to the four "engineered" requirements: **phases** = 1–10; **verification** = phase 7 + citation check; **state** = phase 9 journal; **stop condition** = phase 10 rubric threshold (and a plateau rule: stop if the score does not improve across two successive iterations).
